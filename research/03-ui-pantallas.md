## 2. Flujo de arranque (orden real)

Árbol de proveedores (`xfe`, `index.js:93789-93860`), de fuera a dentro:

1. `ErrorBoundary` global (`93756`, pantalla "Something went wrong / Try again").
2. `LanguageProvider` (`40671`): idioma inicial = `navigator.language[:2]` si es `en|es`, si no `en` (`35504`). Luego llama `launcher_get_settings`; si `settings.language` es válido lo aplica. Cambiar idioma → `launcher_update_settings {language}`.
3. `PerformanceProvider` (`28960`): lee `localStorage["roxy-launcher:low-power-mode"]` → `data-perf="low|high"` y `MotionConfig reducedMotion`.
4. `ToastProvider` (`40635`; duraciones: success/info 4,5 s, warning 7 s, error 9 s).
5. `CloseLauncherDialog` (`92313`) y `UpdateGate` (`93645`).
6. `UpdateGate`: `launcher_check_update` (sin esperar: mientras no hay respuesta pinta los hijos). Si `updateRequired && latestRelease` → **pantalla bloqueante** (fondo wallpaper por defecto + overlay negro 75 %, barra de título propia, icono ⚠️, notas, botón "Update now") (`93663-93720`); si `updateAvailable` → **banner superior** fijo (acento 90 %, "A new version (x) is available. Update | ✕") (`93720-93755`). "Update now" abre `UpdateModal` (`58939-59137`): `updater_check` → prompt (notas, "Not now"/"Update now") → `updater_download_and_install` con evento `update://progress` (`{kind:"progress", downloaded,total}`) y barra → reinicia solo; si no hay build firmado ofrece "Download manually" (`downloadUrl` vía `opener`). Un fallo de `launcher_check_update` se trata como "sin actualización".
7. `AuthProvider` (`28840`): estado `checking|anonymous|authed`. Llama una vez (promesa memoizada a nivel de módulo, `28836`) a `launcher_restore_session`; si devuelve perfil → `authed`, si no/ error → `anonymous`.
8. `AuthGate` (`93637`):
   - `checking` → **pantalla de arranque** (`93606-93636`): wallpaper por defecto + overlay negro 60 %, barra de título propia, spinner y 3 textos que se avanzan con timers cosméticos (350 ms y 700 ms): "Checking launcher account session…" → "Preloading assets…" → "Contacting Minecraft services…" (no hay trabajo real detrás de los dos últimos).
   - `anonymous` → **flujo de login** (abajo).
   - `authed` → resto de proveedores y router.
9. Ya autenticado, dentro de la app: `ProfilesProvider` (`29028`: perfiles de juego = `profile.minecraftAccounts`; activo = el primero si no hay selección; la selección **solo vive en memoria**), `EcosystemProvider` (`36559-36704`: 7 consultas `ecosystem_*` en paralelo + `ecosystem_report_launcher_opened`; si `dailyRewardGranted` → tarjeta "Daily reward credited"), `ThemeProvider` (`59338`), `RunningInstanceProvider` (`35639`), `ActivityProvider` (`40154`: tareas backup/restore para el pill de descargas), `LanProvider` (`37305`), `BrowserRouter`.
10. Latido de presencia: en `authed` llama `launcher_update_presence {isOnline:true}` al entrar y cada 60 s (`28840-28860`, `fZ=6e4`); al cerrar sesión envía `isOnline:false` antes de `launcher_logout`. Al terminar un juego (`mc://exited`) refresca presencia y perfil (`43045`).
11. Tutorial (`Fne`, `42799`): si `profile.hasCompletedTutorial` es falso, 700 ms después arranca el tour driver.js (overlay negro 65 %, `stagePadding 6`, radio 12, progreso visible): (1) bienvenida, (2) panel de cuenta [abre solo el panel `data-tour="account-panel"`], (3) botón "Add game profile" (solo botón cerrar; si el usuario hace clic se interrumpe el tour y, cuando exista un perfil de juego, se reanuda con el tour "rest": selector de versión, Library, Discover, Settings). Al terminar o cerrar → `launcher_complete_tutorial` + refresco de perfil.

### Flujo de login (`dfe`, `92821-93594`) - máquina de estados

Layout común (`xo`, `92532`): barra de título propia arriba a la derecha (min/max/cerrar, `tw` `92380`); a la izquierda columna de formulario (ancho máx. 340 px, centrada: logo 56 px, wordmark "ROXY LAUNCHER" en Monocraft con sombra dura `#3f3f3f`, separador de rombo, el paso actual con `AnimatePresence mode="wait"` y transición 0,22 s, iconos Discord/GitHub y enlaces Privacy · Terms · Support); a la derecha (solo ≥lg, 43 % de ancho, 420-620 px) ilustración vertical con zoom lento 1→1,06→1 (26 s en bucle), degradados laterales, resplandor `--theme-glow` en 78 % 15 % y 8 partículas que caen; en modo bajo consumo se desactivan zoom y partículas. Campos con etiqueta flotante (color #9ca3af → violeta #8b5cf6) y botón ojo para contraseña.

| Estado | Contenido | Comando |
|---|---|---|
| `method` | "Sign in to Roxy Launcher": botón "Continue with Roxy account", separador "or", "Continue with Google" | Google → `launcher_google_sign_in` (resultado `loggedIn` / `needsRegistration` / `needsLink`) |
| `login` | email + password, "Forgot password?", "Create an account" | `launcher_login(email,password,deviceLabel)` → `loggedIn`, o `needsEmailVerify` → OTP "emailVerify", o cualquier otro → OTP "loginOtp" (todo login pide código por email) |
| `register` | email, username (3-20, `[A-Za-z0-9_]`), password (≥8), confirmar | `launcher_register(email,username,password)` → OTP "emailVerify" |
| `otp` | 6 casillas numéricas (auto-avance, pegar, backspace), "Verify", "Resend code" (aviso 4 s), "Back to sign in" | `launcher_verify_code(pendingTicket,code)` (si el ticket era de reset de contraseña devuelve `resetTicket`, si no loguea y entra); `launcher_resend_code` (devuelve ticket nuevo) |
| `googleRegister` | email (solo lectura), username sugerido, password + confirmar | `launcher_google_complete_registration` |
| `googleLink` | "Ya existe una cuenta con ese email": pide la contraseña | `launcher_google_link_existing` |
| `forgot` | email → "Send code" | `launcher_forgot_password` → OTP "passwordReset" |
| `reset` | nueva contraseña + confirmar | `launcher_reset_password(resetTicket,newPassword)`; vuelve a `login` (hay que iniciar sesión de nuevo) |

Errores: texto rojo bajo el botón (`message` del error `{kind,message}` o genérico "Something went wrong — please try again.", "Passwords don't match.", "Invalid or expired code.", "Couldn't resend the code.", "Couldn't reset your password."). Tras `loggedIn` el provider hace `launcher_get_profile` y pasa a `authed`.

Verificación de email posterior (no bloqueante): en el panel de cuenta, si `profile.emailVerifiedAt` es nulo, aviso "Your account isn't verified" + botón → `launcher_resend_verification`.

Cuentas de juego (premium/offline) se piden *después* del login de Roxy: con 0 perfiles, Home muestra el estado vacío "No Minecraft account yet" y el tutorial guía al panel de cuentas.

## 4. Ventana, tema y estilo

**Ventana**: decoraciones propias (se pintan botones minimizar/maximizar-restaurar/cerrar en el island header y, en pantallas previas al login/actualización, en una barra transparente de 3,5 rem arriba a la derecha; arrastre con `startDragging`, doble clic alterna maximizar). Tamaño de diseño **1280×800** (`dO/uO`, `36327`; "Reset resolution" = des-maximizar + `setSize` + `center`); el texto de ajustes dice que se puede redimensionar y maximizar. El botón cerrar sigue la lógica de `closeBehavior` (tray = `window.hide()`; quit = `quit_launcher`; ask = modal). El JS **nunca** llama a `setEffects/clearEffects/setDecorations/setMinSize`, así que blur de ventana, transparencia y tamaño mínimo (si existen) vienen de la config Tauri, no determinable aquí (§7). El blur visual es CSS (`backdrop-filter`) sobre un wallpaper dentro del DOM.

**Tema siempre oscuro**, sin modo claro ni `prefers-color-scheme`. Variables base (`index.css:486-495`, `250-345`): `--color-background #0a0a0d`, `--color-surface #111015`, `--color-surface-raised #17161c`, `--color-glass-surface #ffffff0d`, `--color-glass-surface-hover #ffffff14`, `--color-glass-border #ffffff1a`, `--color-accent #8b5cf6`, `--color-accent-hover #7c3aed`, `--color-text-primary #f5f5f5`, `--color-text-secondary #9ca3af`, `--theme-glow #8b5cf673`, `--theme-glow-soft #8b5cf62e`, `--theme-sidebar-from #15161a`, `--theme-sidebar-to #0c0d0f`, más `--rx-surf-1..3`, `--rx-overlay-1..5`, `--rx-border-1..3` (blancos/negros translúcidos). Verde `#22c55e` para "Play now"/online, rojo `#ef4444`/`#f87171` para peligro, ámbar para monedas/avisos. `.glass-panel` = `backdrop-filter: blur(20px) saturate(150%)`, borde 1 px glass-border, radio 24 px, sombras internas `inset 0 1px #ffffff0d, inset 0 -1px #0003` (`index.css:8409`). Modales: panel `rounded-[24px]` con degradado `#16151b→#0c0c0f`, rejilla decorativa 28 px (`bg-grid-texture`, líneas `#ffffff0d`), halo `--theme-glow`/rojo, scrim `black/80 + blur`. Botón primario = degradado accent-hover→accent, píldora completa, sombra con glow, resplandor radial que sigue al ratón (desactivado en modo bajo consumo); `whileTap` 0,94, `whileHover` 1,015, spring (stiffness 520, damping 24).

**Tema adaptativo según wallpaper** (`58849-59340`, `Kse`/`f6`/`tae`):
1. Fuente del color: wallpaper equipado (cosmético WALLPAPER del ecosistema; si es URL http(s) se descarga vía `ecosystem_fetch_image_data_url` para poder leerlo en canvas) o, si no hay, `background-B516kKkk.webp`.
2. Extracción: dibuja la imagen en un canvas de **48×48**; ignora píxeles con alfa <128; calcula luminosidad media; descarta píxeles con L<0,12, L>0,93 o S<0,12; agrupa el resto en **24 cubos de matiz de 15°** con peso `S² × (0,35 + 0,65·(1−|L−0,5|·2))`; elige el cubo de mayor peso; matiz = media ponderada dentro del cubo, saturación media S; saturación de acento = `clamp(S·1,15, 0,55, 0,9)`; `accent = HSL(matiz, sat, 0,62)`, `accentHover = HSL(matiz, sat, 0,53)`. Si no hay color dominante → `null` → acento por defecto `#8b5cf6`/`#7c3aed` con matiz 258.
3. Ajustes (`launcher_get_settings`, defaults: `accentColor:"auto"`, `themeIntensity:55`, `backgroundBlur:0`, `backgroundDim:40`, `panelOpacity:100`): con acento manual el matiz sale del color elegido y el hover es el mismo matiz con luminosidad −0,09 (mín. 0,32). Intensidad `i=themeIntensity/100`: tinte `u=HSL(matiz,0,85,0,62)`; blanco teñido = mezcla(blanco, u, 0,55·i); saturación del fondo `m=0,04+0,34·i`; base oscura `g=HSL(matiz, m, 0,09)`.
4. Derivadas: `--color-background=HSL(h,0,8m,0,035)`, `--color-surface=HSL(h,m,0,058)`, `--color-surface-raised=HSL(h,m,0,088)`, sidebar de `L 0,095` a `L 0,038`, `--color-glass-border` = mezcla(blanco, u, 0,7·i) con alfa 0,14 (y 0,05/0,08/0,10 para `--rx-border-*`), `--color-text-secondary` = mezcla(#9ca3af, HSL(h,0,3,0,74), 0,55·i), `--theme-glow`=color a alfa 0,45 y `--theme-glow-soft` 0,18. Con `panelOpacity=p/100`: superficies de cristal = mezcla(g → blanco teñido, p) con alfa que va de 0,94 (p=0, "Solid") a 0,06 (p=1, "Maximum"); overlays = mezcla(g → negro, p) análogo.
5. Aplicación: se escriben como propiedades inline en `<html>`; hay `@property` registrados para todas, con `transition` de **0,7 s** en `:root` (se desactiva con `prefers-reduced-motion`) (`index.css:8480-8620`). `--bg-blur` (px) y `--bg-dim` (0-0,85) alimentan el fondo. El tema se persiste con debounce de 500 ms.

**Rendimiento / Linux** (`index.css:8754-8785`): con `data-platform="linux"` los blur se reducen (xl/2xl → 10 px, md → 6 px, sm → 3 px, `glass-panel` → blur(10px) saturate(150%)) y `.glass-panel` usa `will-change` + `translateZ(0)`. Con `data-perf="low"` desaparece todo `backdrop-filter`, `animate-pulse/bounce` y `scroll-behavior`, y `MotionConfig` pasa a `reducedMotion="always"`.

**Animaciones notables**: dock del sidebar con escala por proximidad; indicador deslizante con spring; botones con spring + brillo radial; modales (`scale .95→1`, `y 20→0`, spring 26/320); drawers (x 110 %→0, spring 30/280, mass .9); toasts spring 28/320 con `layout`; carrusel del hero con fundido y desplazamiento; transición de pasos del login 0,22 s con `layout` 0,4 s; zoom lento 26 s y partículas del arte de login; `theme-image-fade-in` 0,6 s del wallpaper; transición de variables de tema 0,7 s; barra de progreso con degradado accent y glow.
